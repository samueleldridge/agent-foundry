# Phase 10b retro

The screens themselves were smooth — the generated-OpenAPI-types workflow meant most API mistakes died at `tsc` rather than at runtime, and shadcn/Tailwind v4 kept the design bar consistent without bespoke CSS. What ate time was environment, not code: repeated session stalls interrupted the implementation agent three times (the orchestrator finished gates/commits inline), and the one genuinely novel bug was Node ≥22's experimental global `localStorage` silently shadowing jsdom's Storage under vitest — every test failed identically, and the fix (a two-line Storage bridge in setup) took longer to diagnose than to write because three plausible causes (jsdom opaque origin, vitest environmentOptions, populateGlobal) had to be eliminated by probing before the real one surfaced. Lesson carried to 10c: probe the runtime directly (the `globalThis.jsdom` handle) before theorizing from configs.
